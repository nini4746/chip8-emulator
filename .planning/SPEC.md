# CHIP-8 에뮬레이터 SPEC

> 학습용 토이. 언어 C + SDL2, 1인 개발, 예상 1주. 이 문서는 구현 정답이 아니라 "무엇을, 어떤 순서로, 완료를 어떻게 판정하는가"를 고정하는 가이드다.

## 이 프로젝트가 만드는 것

`./chip8 <rom경로>` 로 실행하는 원조 COSMAC VIP CHIP-8 에뮬레이터. SDL2 창에 64x32 화면을 띄우고, Timendus chip8-test-suite를 통과하며, Pong과 Tetris가 돌아가면 완료.

## 왜 만드는가

- fetch-decode-execute 사이클, 레지스터, 메모리맵, 타이머를 손으로 익히기 위한 CPU 층 워밍업 (xv6 트랙 전 단계)
- 상세 동기는 README.md 참고

## 확정된 전역 결정

- 변종: 원조 COSMAC VIP CHIP-8만. quirk 프로파일은 VIP 클래식으로 고정, 컴파일 타임 상수로 분리 (학습 후 뒤집어 볼 수 있게)
- 판정 기준 롬: Timendus chip8-test-suite (1-chip8-logo, 2-ibm-logo, 3-corax+, 4-flags, 5-quirks, 6-keypad, 7-beep) + Pong + Tetris
- 실행 속도: CPU 700 IPS, 타이머 60Hz. 두 값은 서로 독립인 상수
- 빌드 환경: macOS + clang + brew SDL2 (pkg-config). 외부 의존성은 SDL2 하나만

## 요구사항

### R1. 셸과 ROM 로딩

1. **검증 문장**: `./chip8 <rom경로>` 실행 시 롬이 메모리 0x200에 적재되고 폰트셋이 0x050~0x09F에 적재된 상태로 에뮬레이션이 시작된다.
2. **현재 상태**: 코드 없음. README만 존재.
3. **목표 상태**: Makefile로 빌드되는 CLI 바이너리. 잘못된 입력은 전부 명시적 에러.
4. **수용 기준**:
   - [ ] 인자 없이 실행하면 usage 출력 후 비정상 종료 코드로 종료
   - [ ] 존재하지 않는 파일 경로에 에러 메시지 출력 후 종료
   - [ ] 3584바이트 (4096 - 512) 초과 롬은 적재 거부 + 에러 메시지
   - [ ] 폰트셋 16글자 (0~F) 가 0x050~0x09F에 적재됨

### R2. CPU 코어 - 옵코드 35개

1. **검증 문장**: 원조 CHIP-8 옵코드 35개 전부가 VIP 의미론으로 실행된다.
2. **현재 상태**: 없음.
3. **목표 상태**: fetch-decode-execute 루프 + 전체 명령어 구현. 스택 16레벨.
4. **수용 기준**:
   - [ ] Timendus 3-corax+ 전 항목 체크 표시
   - [ ] Timendus 4-flags 전 항목 체크 표시 (VF가 피연산자 겸 플래그인 경우 포함 - 플래그 기록이 결과 기록을 이긴다)
   - [ ] 스택 오버플로/언더플로 시 에러 메시지 (PC 포함) 출력 후 정지
   - [ ] 미지 옵코드 (SUPER-CHIP 포함) 를 만나면 PC와 옵코드 값 출력 후 정지

### R3. 디스플레이 - 64x32 모노크롬

1. **검증 문장**: 64x32 프레임버퍼에 XOR 방식으로 그리고, SDL2 창에 정수배 스케일로 렌더링한다.
2. **현재 상태**: 없음.
3. **목표 상태**: 00E0/DXYN이 프레임버퍼를 조작하고, 렌더러는 프레임버퍼만 읽어서 그린다.
4. **수용 기준**:
   - [ ] Timendus 1-chip8-logo, 2-ibm-logo가 깨짐 없이 표시됨
   - [ ] 00E0으로 화면 전체가 지워짐 (로고 롬 실행으로 육안 확인)
   - [ ] DXYN에서 픽셀이 꺼지는 충돌 발생 시 VF=1, 아니면 VF=0 (3-corax+로 판정)
   - [ ] 시작 좌표는 64/32 모듈로 랩, 스프라이트 픽셀은 가장자리에서 클리핑 (5-quirks "clipping" 항목으로 판정)

### R4. 입력 - 16키 키패드

1. **검증 문장**: COSMAC 16진 키패드가 QWERTY 1234/QWER/ASDF/ZXCV에 매핑되어 EX9E, EXA1, FX0A가 동작한다.
2. **현재 상태**: 없음.
3. **목표 상태**: SDL 이벤트 → 키패드 상태 배열 → 옵코드 3종.
4. **수용 기준**:
   - [x] Timendus 6-keypad의 테스트 3종 전부 통과 - 2026-07-14 헤드리스 키 주입(`CHIP8_DUMP_KEYSEQ`)으로 검증: EX9E는 키 5 hold 중에만 셀 반전(`snapshots/6-keypad-ex9e-*.png`), EXA1은 hold 중 눌린 키만 비반전·release 후 16개 전부 반전(`snapshots/6-keypad-exa1-*.png`)
   - [x] FX0A는 키 눌림이 아니라 키 릴리스 시점에 등록됨 (6-keypad로 판정) - 키 8을 150프레임 hold하는 동안 "PRESS ANY KEY" 유지(press 미등록), release 후 "ALL GOOD" (`snapshots/6-keypad-fx0a-*.png`)
   - [ ] ESC로 언제든 정상 종료 (인터랙티브 항목 - 실창 실행 시 확인)

### R5. 타이머와 실행 속도

1. **검증 문장**: delay/sound 타이머는 60Hz로 감소하고, CPU는 700 IPS로 실행되며, 두 속도는 서로 독립이다.
2. **현재 상태**: 없음.
3. **목표 상태**: 메인 루프가 프레임 페이싱으로 타이머 60Hz와 CPU 700 IPS를 각각 유지. 두 값 모두 이름 붙은 상수.
4. **수용 기준**:
   - [ ] 60초 실행 시 타이머 감소 횟수가 3600회 ±5% (로그로 측정)
   - [ ] IPS 상수를 바꿔도 타이머 속도가 변하지 않음 (상수 2배로 바꿔 재확인)
   - [ ] 유휴 시 CPU 점유율이 한 코어를 다 먹지 않음 (top으로 확인 - busy-spin 없음)

### R6. 사운드 - 비프

1. **검증 문장**: sound 타이머가 0보다 큰 동안 가청 비프음이 난다.
2. **현재 상태**: 없음.
3. **목표 상태**: SDL2 오디오로 단순 사각파/톤 출력. 파형 품질은 무관.
4. **수용 기준**:
   - [x] Timendus 7-beep 실행 시 화면 표시와 동기해 소리가 들림 - 2026-07-14 이중 검증: (1) `CHIP8_BEEP_LOG` 프레임 트레이스에서 스피커 아이콘(22픽셀) 표시 구간과 sound_timer>0 구간이 프레임 단위 동기(ST 9→1, 17프레임 주기), (2) `SDL_AUDIODRIVER=disk`로 실제 SDL 오디오 파이프라인 출력 캡처 - 440Hz(측정 438~441) ±6000 2레벨 정사각파, 비프 139~476ms 세그먼트가 무음과 교대. 가청 여부 최종 확인만 스피커 필요

### R7. 호환성 - VIP quirk 프로파일

1. **검증 문장**: quirk 6종이 VIP 클래식 동작으로 고정되어 있고, 표준 테스트 롬과 실제 게임이 돌아간다.
2. **현재 상태**: 없음.
3. **목표 상태**: 아래 quirk가 컴파일 타임 상수로 분리된 채 VIP 값으로 고정:
   - 8XY1/2/3 실행 후 VF=0 리셋
   - FX55/FX65 실행 후 I = I + X + 1
   - 8XY6/8XYE는 VY를 시프트해서 VX에 저장
   - DXYN 스프라이트는 가장자리 클리핑
   - DXYN은 프레임당 1회만 실행 (display wait)
   - BNNN은 NNN + V0으로 점프
4. **수용 기준**:
   - [ ] Timendus 5-quirks에서 CHIP-8 선택 시 6개 항목 전부 정상 판정
   - [x] Pong: 60초 플레이 동안 크래시 없음, 매핑 키에 패들 반응, 화면 깨짐 없음 - 2026-07-14 헤드리스 3600프레임(60초분) exit 0, `CHIP8_SEED` 고정 두 런(무입력 vs 키 1/4 주입) 비교로 패들 위치·스코어 분기 = 키 반응 실증 (`snapshots/pong-keyresponse.png`), 스냅샷 화면 정상
   - [x] Tetris: 60초 플레이 동안 크래시 없음, 매핑 키에 블록 반응, 화면 깨짐 없음 - 동일 방법, 키 4 주입 시 같은 프레임(f120)에서 피스 위치 이동 확인 (`snapshots/tetris-keyresponse.png`), 3600프레임 exit 0. 실시간 "플레이감"(입력 지연 체감)만 실창 필요

## 부정 수용 기준 - 이렇게 되면 실패

- [ ] I 또는 PC가 4KB 범위를 벗어나도 에뮬레이터 프로세스 메모리를 침범하지 않는다 (마스킹 또는 에러 정지 중 하나로 방어)
- [ ] SUPER-CHIP 옵코드를 조용히 구현하거나 조용히 무시하지 않는다 (미지 옵코드 처리 경로로 정지)
- [ ] 화면에 그리는 유일한 경로는 64x32 프레임버퍼다 (옵코드가 SDL을 직접 호출하지 않음)
- [ ] 메인 루프가 sleep/페이싱 없이 CPU를 태우지 않는다

## 범위 안에 있는 것

- 옵코드 35개 전부 (VIP 의미론)
- 4KB 메모리, V0~VF, I, PC, SP, 스택 16레벨, 타이머 2개
- SDL2 창 렌더링 (정수배 스케일), 16키 입력, 단순 비프
- quirk 6종의 컴파일 타임 상수 분리
- Makefile, 명시적 에러 처리 (파일/크기/스택/미지 옵코드)

## 범위 밖에 있는 것 - 이유 포함

- SUPER-CHIP / XO-CHIP 확장: 옵코드와 해상도가 달라 별개 프로젝트 분량. 다음 확장 후보
- 런타임 quirk 토글 (CLI 옵션/설정 파일): 학습 목적엔 컴파일 타임 상수로 충분
- 디버거/디스어셈블러 UI: 1주 분량 초과. printf 디버깅으로 충분
- 세이브 스테이트 / 되감기: 학습 목표 (CPU 사이클) 와 무관
- Windows/Linux 패키징: macOS 빌드만 보장. 코드가 이식 불가능할 이유는 없지만 검증 안 함
- 사운드 파형/볼륨 옵션: 가청 여부만이 목표
- FX1E의 VF 변경 (Amiga quirk): 목표 롬 어느 것도 사용하지 않음

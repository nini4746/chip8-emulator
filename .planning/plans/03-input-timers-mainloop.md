# Plan 03: 입력, 타이머, 메인 루프 타이밍

## 이 plan의 목표

키패드 입력과 60Hz 타이머, 700 IPS 실행 속도를 붙여서 "실제로 조작 가능한" 에뮬레이터로 만든다. SPEC의 R4 전체와 R5 전체를 담당한다.

## 시작 전에 알아야 할 컨텍스트

- plan 02까지 만든 것: 옵코드 35개 전부 (EX9E/EXA1/FX0A와 타이머 옵코드는 상태 배열만 읽고 씀), 키패드 상태 배열, 타이머 필드
- 키 매핑 (COSMAC 16진 키패드 → QWERTY):
  ```
  1 2 3 C        1 2 3 4
  4 5 6 D   →    Q W E R
  7 8 9 E        A S D F
  A 0 B F        Z X C V
  ```
- 핵심 개념 (이 토이의 학습 포인트): CPU 속도 (700 IPS) 와 타이머 속도 (60Hz) 는 별개의 시계다. 일반적 구조는 60Hz 프레임 루프 안에서 명령을 IPS/60개씩 실행하고 타이머를 1 감소시키는 것 - 다른 구조도 가능하나 두 속도의 독립만 지키면 된다
- VIP quirk 하나가 여기 속한다: DXYN display wait (DXYN은 프레임당 1회만 실행). 5-quirks의 "disp.wait" 항목이 이걸 검사한다
- FX0A는 키 눌림이 아니라 키 릴리스 시점에 등록 (VIP 동작). 6-keypad가 이걸 검사한다

## 해야 할 작업

1. SDL 이벤트 루프에서 KEYDOWN/KEYUP을 키패드 상태 배열 16칸에 반영. ESC는 종료 유지
2. EX9E/EXA1이 상태 배열을 읽어 스킵. FX0A는 릴리스 감지 (눌린 키 기억 후 릴리스 시점에 VX 기록, 그 전에는 PC를 전진시키지 않는 방식 등)
3. 메인 루프를 프레임 페이싱 구조로: 60Hz마다 타이머 감소 + 렌더 + 프레임당 IPS/60 명령 실행. IPS와 타이머 주파수를 이름 붙은 상수로. sleep 또는 vsync로 페이싱 (busy-spin 금지 - 부정 기준)
4. DXYN display wait 구현 (프레임당 draw 1회)
5. 검증용 임시 로그: 타이머 감소 횟수 카운터 (검증 후 제거하거나 컴파일 플래그 뒤로)

## 빠지면 실패인 것

- IPS와 60Hz의 독립 (타이머가 명령 개수에 묶이면 R5 실패)
- FX0A의 릴리스 의미론
- 프레임 페이싱 (없으면 CPU 한 코어를 태운다)

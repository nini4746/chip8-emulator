# 0003. CPU 코어와 SDL 계층을 파일로 분리

- 상태: 채택
- 날짜: 2026-07-13

## 맥락
옵코드가 SDL을 직접 호출하면 화면 출력 경로가 여러 갈래가 되고, 코어를 창 없이 실행할 수 없다. 화면에 그리는 유일한 경로는 64x32 프레임버퍼여야 한다는 것을 부정 수용 기준으로 두었다.

## 결정
- `chip8.c`: 순수 CPU 코어. SDL을 포함하지 않는다. 상태는 `chip8_t` 하나다.
- `platform.c`: SDL2 계층(창, 키 입력, 오디오, BMP 저장). `platform_t`는 불투명 타입이고, 코어 구조체 대신 `display`와 `keypad` 배열만 받는다.
- `main.c`: CLI와 프레임 루프로 둘을 연결한다. 의존 방향은 `main.c -> chip8.h, platform.h` 한 방향이다.

## 대안
- 옵코드에서 SDL 직접 호출: 코어를 SDL 없이 실행할 수 없고, 프레임버퍼 외의 그리기 경로가 생긴다.

## 결과
- 장점: 옵코드 -> 프레임버퍼 -> 렌더러가 단방향이다. 코어를 헤드리스로 실행할 수 있어 검증 훅([0007](0007-env-gated-headless-hooks.md))의 기반이 된다.
- 단점/감수한 점: SDL 계층은 코어 상태 전체가 아니라 `display`, `keypad` 배열만 볼 수 있다. 다른 상태가 필요하면 `main.c`가 전달해야 한다(예: `platform_set_beep(sound_timer > 0)`).
